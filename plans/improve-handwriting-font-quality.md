# Plan: 손글씨 폰트 품질 개선 — 원인 기반 전면 재정비
_Created: 2026-07-03 | Status: done (Step 1~9 완료, Step 10은 사용자 선택 대기)_

## Problem

몇 장의 원본 손글씨 스캔으로 2,350자 한글 폰트를 생성 중이나 결과물이 "애매함"
(획 끊김, ㅇ 뚫림, 획이 지나치게 가늚, 글자 누락). 이번 세션 조사로 원인이
추측이 아닌 **관측된 사실**로 확정됨:

1. **문자셋 오염 (치명적)**: `generator.py`의 `COMMON_2350_HANGUL` 하드코딩 문자열이
   길이 2,512 / 유일 글자 2,098자. 표준 KS X 1001 대비 **376자 누락**
   (너·널·넘·능·많·당·듣·네 등 초고빈도 글자 포함), 표준 외 글자 124자 혼입.
   → 폰트에서 이 글자들이 아예 안 나옴.
2. **스타일 힌트 오염 (품질의 근원)**: `data/style/C544.png`('아')에 ㅇ이 없음
   (모음 단독 `ㅏ.JPG`에서 조작 생성). 전 힌트가 노이즈 점 다수 + 여백 없는
   타이트 크롭 + 저해상도. 원본에 있는 '실'(C2E4), '효'(D6A8)는 힌트로 미사용.
   → 생성된 '아'의 ㅇ 뚫림이 이것의 직접 결과.
3. **픽셀 평균 스타일 앙상블 결함**: 서로 다른 글자 이미지를 픽셀 공간에서
   평균(`generator.py:347-349`) → 스타일 인코더에 유령처럼 겹친 이미지가 입력됨.
   FontDiffuser는 단일 참조 이미지 전제 모델.
4. **파괴적 후처리**: 고정 threshold 175 + 고정 CC 400px 필터를 2,350자 전체에
   일괄 적용 → 관측 결과 '가'의 ㄱ이 두 조각으로 끊기고 전체 획이 앙상하게 마름.
   글자마다 잉크량이 다른데 상수 하나로 처리하는 구조적 문제.
5. **직선 폴리라인 벡터화**: `vectorize.py`가 M/L 명령만 사용(베지어 없음)
   → 확대 시 각진 윤곽, 손글씨 질감 상실.
6. **고정폭 메트릭**: `build_font.py`가 전 글리프 width=1024 모노스페이스
   → 조판 시 어색한 간격.

## Constraints

- 사전학습 FontDiffuser는 96×96 해상도 고정 (재학습 없이는 해상도 상향 불가).
- 스타일 원본은 저품질 스캔 3종(매실효소/이새별/조영화), 실사용 가능 글자 10자뿐
  (매·실·효·소·이·새·별·조·영·화). 받침 커버리지는 실·별·영 3자, ㅓ/ㅜ/ㅡ 모음 힌트 전무.
- 최대 개선 수단은 **사용자의 새 손글씨 샘플**(흰 종이에 ~30자)이나, 이는 사용자
  입력이 필요하므로 선택 단계로 분리. 그 전까지는 기존 10자에서 최대치를 뽑는다.
- TTF 빌드는 FontForge ffpython 환경 필요 (Windows).
- 2,350자 전체 추론은 GPU 시간이 듦 → 파라미터 튜닝은 고정 표본(~30자)으로 A/B 후
  전체 재생성은 마지막 1회만.

      content_encoder에도 그대로 통과되어 "참조 글리프 구조" 조건으로도 쓰임을
      확인 — 서로 다른 글자의 픽셀 평균은 스타일·구조 두 경로 모두에 프랑켄글리프를
      주입하는 구조적 결함이었음. 임베딩 평균 대신 **단일 최적 참조 선택**
      (`get_best_style_char`)으로 확정. A/B 결과(표본 84~94자, 결함탐지 하네스,
      보정된 fragmentation 규칙 적용): 구 파이프라인(오염된 힌트+픽셀평균) 14.3%
      의심 → 신 파이프라인(재구축 힌트+단일참조) **5.3%** 의심. 잔여 결함은
      고정 threshold로 인한 옅은 글자 공백화(예: '나') — Step 5에서 해결 예정.
- [x] Step 5 — **적응형 후처리로 교체**: 완료. 고정 175 threshold → 글리프별
      Otsu 적응형(실측 133~156 범위, 175는 항상 너무 높아 옅은 글자를 통째로
      날리고 있었음 — 예: '나' 완전 공백화). 추가로 **진짜 근본 원인 발견**:
      방향별 morphological closing이 배경(255)이 다수인 극성 그대로 적용되고
      있어서 "획을 잇는" 의도와 반대로 얇은 잉크 획을 깎아내고 있었음 — 이게
      baseline에서 '가'의 ㄱ이 두 조각났던 진짜 원인. 잉크=255로 반전 후 closing
      적용하도록 수정, CC 필터도 고정 400px → 글리프별 총 잉크량 비례(0.4%)로
      교체. 검증(raw 출력 캐시 재사용, 표본 94자): 5.3%→4.3% 의심, '나' 공백
      해결, '가'의 ㄱ 끊김 완전 해결(육안 확인). `postprocess_glyph()`로 통합해
      `generator.py`에 반영 완료, 3자 스모크 테스트로 엔드투엔드 배선 확인.
- [x] Step 6 — **전체 재생성**: 완료. 확정된 파이프라인으로 2,350자 전량 GPU

- [x] Step 7 — **벡터화 개선** (`vectorize.py`): 완료. cv2.approxPolyDP로 외곽선
      단순화(둘레 비례 epsilon) 후 Catmull-Rom→3차 베지어 변환으로 M/L 직선

      비교 — 새 경로가 확대 시 각짐 없이 매끄러움 확인 (브라우저 스크린샷 도구가

      설정(1000/800/200), space 글리프(U+0020) 추가. 검증: 160자 스모크
      테스트 폰트를 빌드해 PIL로 문장 렌더링 — 폭이 제각각인 글자들이

      distanceTransform으로 획 두께 측정 후 중앙값(8.31px) 기준 침식/팽창으로
      정규화. 부작용 검증: ㅁ/ㅇ/ㅂ 등 홀(hole) 보존 확인(몸/밥/앉 육안 검사),
      결함 하네스 재측정 6.8%(악화 없음, 오히려 소폭 개선). 정규화 후 재벡터화

      4.8~13.7px → 6.1~12.3px로 수렴.
